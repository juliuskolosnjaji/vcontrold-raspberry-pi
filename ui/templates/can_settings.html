CAN-Einstellungen

Konfiguriert config/can_mapping.json: Bitrate, eigene Knoten-Nummer und welche Werte per CAN gesendet bzw. empfangen werden. Die Abschnitte unten nutzen ausschließlich bestätigte, an echter Hardware verifizierte Formate (siehe README Abschnitt 3.3-3.5) -- CAN-IDs sind erst nach dem CAN-Sniffer-Vorgehen bekannt, bis dahin einfach leer lassen. Neue schreibbare CAN-Variablen (unabhängig von vito.xml, Home Assistant ↔ UVR ohne Vitotronic) legst du auf der eigenständigen MQTT-Variablen-Seite an -- hier trägst du den Namen dann nur noch als Kanal ein.

CAN-Analog-/Digitalausgänge empfangen (bestätigtes Format)

Liest die tatsächlichen "CAN-Analogausgänge"/"CAN-Digitalausgänge" der UVR direkt (siehe README Abschnitt 3.4/3.5) -- je eine CAN-ID für alle 16 Ausgänge einer Spalte, per Sniffer ermitteln. Kanalname per Dropdown aus bestehenden Variablen wählen oder frei eintippen (legt bei Bedarf eine neue MQTT-Variable an). Digital published "ON"/"OFF". Soll ein Wert zusätzlich einen echten Set-Befehl in der Vitotronic auslösen, auf der MQTT-Variablen-Seite unter "Set-Weiterleitung" einrichten.

TA-Netzwerkausgänge senden (bestätigtes Schema)

Sendet immer den MQTT-Topic heizung/<Name> — nie direkt einen Vcontrold-Wert. Vcontrold und CAN sind komplett getrennte Prozesse (orchestrator.py bzw. can-node.py); die einzige Verbindung zwischen ihnen ist MQTT (siehe README "MQTT-Architektur"). Trag hier also den Namen eines MQTT-Topics heizung/<Name> ein (ohne das Präfix heizung/), dessen aktuellen Wert can-node per CAN im tatsächlich von TA verwendeten Format sendet (COB-ID 0x200/0x280/0x300/0x380 + Eigene Knoten-Nummer für Analog, 0x180 + Eigene Knoten-Nummer für Digital — siehe README Abschnitt 3.3). "Ausgang" ist hier keine UVR-Nummer, sondern deine frei gewählte Sendekanal-Nummer -- auf der UVR muss dafür ein "CAN-Analogeingang"/ "CAN-Digitaleingang" mit Knotennummer = deine "Eigene Knoten-Nummer" oben und Ausgangsnummer = dieselbe Zeilennummer hier angelegt werden. Am besten nur so viele Zeilen belegen wie Werte gebraucht werden, jede Variable in genau einer Zeile.

Die Vorschlagsliste im Freitextfeld zeigt alle vito.xml-Variablen (siehe Variablen-Seite), weil das der häufigste Fall ist — eine vito.xml-Variable landet aber selbst nur dann auf heizung/<Name>, wenn sie zusätzlich einem Lese-Zyklus zugeordnet ist (Abschnitt "MQTT-Konfiguration"/"Zyklen"). Ohne Zyklus steht auf dem Topic nie ein Wert, und can-node sendet nichts. Genauso kannst du einen Namen eintragen, der gar nicht aus vito.xml stammt — solange irgendetwas (z.B. Home Assistant direkt) auf heizung/<Name> published, sendet can-node diesen Wert, unabhängig von der Quelle. Analog-Kodierung ist gegen echte Hardware bestätigt, Digital noch nicht getestet.

Diese Tabelle ist der einzige Weg, einen Wert per CAN an die UVR zu senden — ein Name, der hier steht, wird automatisch bei jeder Änderung gesendet, ohne dass an anderer Stelle noch etwas konfiguriert werden muss. Für die Gegenrichtung (ein von der UVR empfangener Wert soll einen echten Set-Befehl in der Vitotronic auslösen) siehe MQTT-Variablen → "Set-Weiterleitung".
