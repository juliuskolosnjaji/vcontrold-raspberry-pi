MQTT-Variablen

Zentrale Definition aller MQTT-Variablen: Anzeigename in Home Assistant + ob/wie eine Variable per MQTT setzbar ist. Unabhängig davon, ob der Wert aus vito.xml (Vcontrold) oder direkt von CAN stammt -- weder Bestandteil der Vcontrold- noch der CAN-Einstellungen-Seite. Welchem Lese-Zyklus eine vito.xml-Variable zugeordnet ist, bleibt auf der Vcontrold-Seite; welche CAN-ID/welcher Sendekanal eine Variable nutzt, bleibt auf der CAN-Einstellungen-Seite.

vito.xml-Variablen

Erscheint automatisch, sobald vito.xml einen Getter dafür hat. "Anzeigename" ändert nur den in Home Assistant angezeigten Namen (leer = automatisch aus dem Variablennamen abgeleitet), getTempKsoll/setTempKsoll bleiben unverändert. "Schreibbar" ist nur wählbar, wenn vito.xml einen Setter hat -- macht die Variable per heizung/cmd/<Name> setzbar (Home Assistant und/oder CAN-Weiterleitung).

Set-Weiterleitung (empfangener Wert → Vitotronic-Parameter setzen)

Anwendungsfall: ein Wert, den du woanders bereits als MQTT-Variable hast (typischerweise ein von der UVR per CAN empfangener Wert, z.B. ein dort berechneter Raumsollwert), soll einen echten Set-Befehl in der Vitotronic auslösen -- nicht nur angezeigt werden. Beispiel: die UVR ermittelt einen neuen Raumsollwert und sendet ihn per CAN an den Pi (siehe CAN-Einstellungen → "CAN-Analogausgänge empfangen", dort als eigene Variable eintragen, z.B. uvr_raumsollwert). Hier trägst du dann uvr_raumsollwert als Quelle ein, TempRaumNorSoll als Ziel -- der Orchestrator setzt den Wert dann in der Vitotronic und verifiziert ihn.

Wichtig: Für die umgekehrte Richtung -- ein Vcontrold-/MQTT-Wert soll per CAN an die UVR gesendet werden -- ist diese Sektion nicht zuständig, dafür die 16-Slot-Tabelle "TA-Netzwerkausgänge senden" auf der CAN-Einstellungen-Seite: dort einfach den Variablennamen eintragen, fertig -- er wird automatisch bei jeder Änderung gesendet, ohne dass hier zusätzlich etwas konfiguriert werden muss. Deshalb akzeptiert das "Ziel"-Feld hier ausschließlich Vitotronic-Parameter, die oben als "Schreibbar" aktiviert sind -- ein CAN-Ziel würde hier ohnehin nie tatsächlich am CAN-Bus ankommen.
